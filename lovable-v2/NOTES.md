# Fémini Stock · نسخة Lovable v2 (نسخة إضافية)

نسخة إضافية من النظام بتصميم جديد (TanStack Start + React + Tailwind). **مش هي النسخة الشغالة على السيرفر.**
النسخة الشغالة هي `php-app/` (MySQL على cPanel)؛ والنسخة دي بياناتها بتتخزن في **متصفح كل جهاز** (localStorage + IndexedDB) ومفيش فيها أي ربط بالسيرفر.

## مين فين
| النسخة | المسار | البيانات |
|---|---|---|
| PHP + MySQL (الشغالة) | `php-app/` | السيرفر |
| Brand 2 (ملف HTML واحد) | `apps/edition-3-brand-v2/` | متصفح الجهاز |

## التشغيل
```sh
cd lovable-v2
npm install        # أو bun install
npm run dev        # تطوير
npm test           # الاختبارات (70)
npm run build
```
ملف `.env.example` فيه أسماء المتغيرات فقط. الملف الحقيقي `.env` مش مرفوع.

## اللي اتصلّح في الإصدار ده
بعد مراجعة كود، اتصلحت 7 أخطاء ومعاها اختبارات في `src/femini/data/regressions.test.ts`:

1. **عكس ورقة شحن** بعد إلغاء أوردر منها مع إرجاع المخزون كان بيرجّع القطع مرتين، وكان بيرجّع الأوردر الملغي مفتوح. دلوقتي بيتخطى اللي رجعت قطعه والملغي يفضل ملغي، والمستلزمات بتتعدّل بنفس المنطق.
2. **إلغاء أوردر بعد مرتجع له** مع "إرجاع المخزون" كان بيرجّع القطع تاني. دلوقتي بيتربط بمستند المرتجع بدون حركات جديدة.
3. **رقم البيك أب** كان بيتكرر بعد أرشفة آخر بيك أب. دلوقتي الترقيم بيحسب المؤرشف كمان، والاسترجاع بيتم رفضه لو الرقم مستخدم.
4. **النسخة الاحتياطية بعد "هولد"** كانت بتترفض (`EXT_HOLD` مش في القايمة).
5. **بيانات متصفح تالفة أو من إصدار تاني** كانت بتتبدّل ببيانات فاضية في أول حفظ. دلوقتي بتتحفظ نسخة منها تحت `femini-web-demo-2-unreadable` قبل أي حاجة.
6. **تاريخ الإلغاء والإقفال التلقائي** كانوا بيقارنوا بتاريخ UTC بدل تاريخ القاهرة (إلغاء الساعة 00:30 كان بيتحسب على اليوم اللي قبله).
7. **مطابقة بوليصة فيها حروف كبيرة** في المسح وفي إلغاء الأوردر.

كمان: ترتيب كروت "خروج" في صفحة العمليات بقى: أوردرات اتشحنت ← توريد للمحل ← هولد.
