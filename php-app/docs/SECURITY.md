# الأمان: إيه اللي محمي وإيه اللي لازم تعمله

## اللي النظام بيعمله
| الموضوع | الحماية |
|---|---|
| **كلمات السر** | `bcrypt` (cost 12). الحد الأدنى 8 حروف، والحد الأقصى 72 (حد bcrypt)، وبيرفض الشائعة (`12345678`, `password123`...) واللي فيها اسم المستخدم أو حرف واحد متكرر. مفيش كلمة سر مخزّنة نص عادي ولا مبعوتة في أي رد. |
| **الدخول** | جلسة سيرفر (`HttpOnly`, `SameSite=Lax`, `Secure` على HTTPS)، تجديد معرّف الجلسة بعد الدخول، **قفل بعد 5 محاولات غلط** للاسم (و15 للـ IP) لمدة 15 دقيقة، ورد واحد ووقت واحد سواء الاسم موجود أو لأ. |
| **انتهاء الجلسة** | بعد 12 ساعة من غير نشاط، وبعد 7 أيام مهما حصل. |
| **تغيير كلمة السر** | لازم كلمة السر الحالية (لنفس المستخدم). التغيير أو إعادة التعيين من المدير **بيخرّج كل جلسات المستخدم التانية** فورًا. تعطيل أو أرشفة مستخدم بتخرّجه في أول طلب. |
| **CSRF** | توكن في كل كتابة + فحص `Origin`. |
| **الصلاحيات** | بتتفحص **على السيرفر** في كل طلب (الدور بيتقرا من القاعدة، فتغيير الدور بيسري فورًا). الواجهة بتخفي الأزرار بس للراحة. |
| **الدفتر** | الحركات إضافة فقط، المستند المؤكّد مجمّد، الأيام المقفولة ما بتقبلش حاجة، والعدّادات ما بترجعش. اسم المنفّذ بيتكتب من الجلسة، فسجل النشاط مينفعش يتزوّر من المتصفح. |
| **SQL** | كل الاستعلامات prepared statements (مفيش دمج نصوص من المستخدم في SQL). |
| **الملفات** | برّه الـ web root، أسماء عشوائية، النوع بيتفحص بمحتوى الملف (PHP/HTML/SVG مرفوضين)، حد حجم، والتنزيل بـ `Content-Disposition` و`CSP: sandbox` و`nosniff` وبعد فحص الجلسة بس. |
| **الهيدرز** | `Content-Security-Policy` (للـ API: `default-src 'none'`، للتطبيق: نفس الأصل + cdnjs للمكتبات + خطوط Google)، `X-Frame-Options: DENY`، `nosniff`، `Referrer-Policy`، `Permissions-Policy`، و`HSTS` على HTTPS. |
| **الأخطاء** | مبتتعرضش للزوار (`display_errors` مقفول)، وتفاصيلها في `error_log` بس. |
| **المثبّت** | محتاج `install_key`، بيفحص البيئة، بيقفل نفسه (`storage/installed.lock`) بعد التثبيت، وبيرفض لو فيه مستخدمين. |

## حدود لازم تعرفها
- **`script-src 'unsafe-inline'`:** التطبيق ملف واحد بسكريبت داخلي، فمش ممكن نقفل inline scripts بدون إعادة كتابته. الحماية الأساسية من XSS هي إن كل نص بيتعرض بيعدّي على `esc()`، والـ CSP بيمنع باقي الأنواع (الاتصال بمواقع تانية، الإطارات، الكائنات).
- **المكتبات من CDN:** SheetJS وhtml2canvas وjsPDF بتتحمّل من `cdnjs.cloudflare.com` بدون SRI. لو عايز أعلى مستوى، نزّلها وحطّها في `public/assets` وغيّر الـ `src`.
- **أي مستخدم داخل بيقدر ينزّل أي ملف** بالـ id (مفيش فصل ملفات حسب الدور). الملفات هي ملفات التشغيل نفسها.
- **مفيش مصادقة ثنائية (2FA)** ولا إعادة تعيين كلمة سر بالإيميل. المدير بيعيّن كلمة سر جديدة للموظف.
- **لا توجد حماية من DoS** غير الحدود الأساسية. استضافتك أو Cloudflare هي اللي بتتحمّل ده.
- **اتجرّب على PHP 8.3 وMariaDB 10.11 بس.**

## قبل ما تفتح السيستم للموظفين (قايمة)
1. HTTPS شغّال (AutoSSL) وكل `http://` بيتحوّل.
2. `config/config.php` موجود، **صلاحياته 640 أو 600**، ومش متاح من المتصفح (جرّب تفتح `https://موقعك/config/config.php` ولازم يرجع 403/404، أو الأفضل يكون برّه الـ web root).
3. `app.debug = false` و`install_key` اتغيّر.
4. **امسح `public/install.php`** بعد التثبيت.
5. `php tools/check.php` ما فيهوش `FAIL`.
6. كلمة سر المدير جملة طويلة، ومحدش بيشاركها. كل موظف له حساب.
7. جدولت النسخ الاحتياطي (قاعدة + `storage`) وجرّبت **تسترجع** نسخة على قاعدة تانية مرة.
8. موظف تجريبي (دور `pack`): اتأكد إنه مبيشوفش إعدادات ولا بيقفل يوم.

## الإبلاغ
لو لقيت ثغرة أو سلوك غريب في الصلاحيات، سجّل الخطوات وابعتها، وما تستخدمهاش على بيانات حقيقية.
