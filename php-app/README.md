# Fémini Stock · نسخة PHP + MySQL (cPanel)

نسخة إضافية من نظام المخزن بتشتغل على **استضافة cPanel عادية (PHP + MySQL)** بدل تخزين المتصفح. موجودة في فولدر منفصل عشان نقدر نقارن الكود بالنسخة العادية (`apps/edition-3-brand-v2`) ونرجع ليها في أي وقت. التطبيق نفسه (الشاشات والمنطق) هو نفس الكود حرفيًا، والفرق كله في طبقة الحفظ والدخول.

> **الحالة:** جاهزة للنشر على cPanel ومختبرة. دخول حقيقي، مزامنة بين الموظفين، قواعد الصلاحيات والقفل والدفتر على السيرفر، مستخدمين وأدوار قابلة للتعديل، **الصور والملفات الأصلية على السيرفر**، استيراد نسخة احتياطية، مثبّت ويب وفحص جاهزية (`tools/check.php`) وحزمة نشر (`tools/build_release.sh`). **لسه:** تجربة على استضافة cPanel حقيقية. التفاصيل في [`docs/COMPARE.md`](docs/COMPARE.md).

## إزاي بيشتغل
```
المتصفح (نفس التطبيق)            PHP على cPanel                       MySQL
 S (الحالة في الذاكرة) ──push──▶  Rules: صلاحيات، أيام مقفولة،  ──▶  moves (إضافة فقط)
        ▲                         مستندات مجمّدة، عدّادات           docs, orders, pickups ...
        └────pull كل ~12 ث──────  Auth: جلسة + CSRF + حماية تخمين   users, roles, audit, files
```
1. الصفحة بتفتح والسيرفر حاطط فيها **الحالة الكاملة** (`window.FEM_BOOT`)، فالتطبيق بيبدأ بداتا حقيقية بدون تحميل.
2. أي تغيير في المتصفح (`save()`) بيتحوّل لـ **diff** (اللي اتضاف أو اتعدّل أو اتأرشف) ويتبعت `POST /api/sync/push` داخل **transaction واحدة**.
3. السيرفر بيطبّق القواعد وبيرفض اللي مش مسموح. لو رفض أو لقى تعارض (موظف تاني عدّل نفس الصف) ← **ولا تغيير بيتطبّق**، والصفحة بتتحدّث من السيرفر.
4. كل ~12 ثانية `GET /api/sync/pull?since=N` بيجيب تغييرات الباقيين.

## أمان
- كلمات السر `password_hash`، جلسة `HttpOnly` + `SameSite=Lax` (+`Secure` على HTTPS)، توكن CSRF لكل كتابة، قفل بعد محاولات غلط (5 للاسم، 15 للـ IP كل 15 دقيقة)، وتجديد معرّف الجلسة بعد الدخول.
- كل استعلام SQL **prepared statement**. الأخطاء مبتتعرضش للزوار.
- كلمات السر `bcrypt` cost 12 مع سياسة بسيطة (4 حروف على الأقل، قرار المالك؛ الحماية من التخمين بالقفل)، انتهاء جلسة (12 ساعة خمول / 7 أيام)، تغيير كلمة السر بيخرّج باقي الأجهزة، فحص `Origin`، و`CSP`/`HSTS`/`X-Frame-Options`. التفاصيل وقايمة ما قبل الفتح في [`docs/SECURITY.md`](docs/SECURITY.md).
- الصلاحيات تتفحص **على السيرفر** في كل push، مش بس في الواجهة. الدور والصلاحيات بتتقرأ من القاعدة مع كل طلب، فتعطيل مستخدم بيسري فورًا.
- الدفتر (`moves`) إضافة فقط: مفيش `UPDATE` ولا `DELETE` في الكود، ومستند مؤكّد مجمّد، والأيام المقفولة ما بتقبلش حاجة، والعدّادات ما بترجعش لورا. **اسم اللي عمل الحدث بيتكتب من الجلسة**، مش من المتصفح.
- الملفات برّه الـ web root بأسماء عشوائية، النوع بيتفحص بمحتوى الملف (مش بالامتداد)، والتنزيل بس عبر الـ API بعد فحص الجلسة.
- لا يوجد حذف: المستخدمين والمسودات والبيك أب بتتأرشف. الـ API مفيهوش `DELETE` خالص.

## المحددات (بصراحة)
- **التعارض بيتحل بالرفض:** لو موظفين اتحركوا في نفس اللحظة، التاني بيتعمله reload وبيعيد العملية. مفيش دمج تلقائي.
- **التحديث polling** كل ~12 ثانية (استضافة مشتركة بدون websockets).
- **مفيش وضع بدون نت.** لو الاتصال قطع، التغييرات بتستنى وبتتبعت لما يرجع (والشاشة بتحذّر).
- **الأدوار الأربعة ثابتة في العدد** (مدير، مشرف، موظف شحن، مراجعة): تقدر تعدّل صلاحيات الثلاثة الأخيرين، مش تضيف أدوار جديدة.
- **مفيش 2FA** ولا إعادة تعيين كلمة سر بالإيميل، والمكتبات والخطوط متخزّنة محليًا. التفاصيل في `docs/SECURITY.md`.
- **الداتا التجريبية معطّلة** عمدًا.
- اتجرّب على PHP 8.3 وMariaDB 10.11. الكود بيستهدف PHP 8.1+ وMySQL 5.7+/MariaDB 10.3+، بس نسخ الاستضافة الأقدم/الأحدث لازم تتجرّب.
